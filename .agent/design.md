## 二、Kumo 未覆盖、本项目自定的部分

### ① 控件高度三档 ⭐

**Kumo 16 条里没有控件高度条目**，但高度差造成的视觉重量差与 `shadow-borders` 同源。
本项目曾同时存在 **26/28/30/32/36/38px 六种**可点物高度，肉眼表现为
「有的控件比旁边的重」——Kumo 的任何断言都不会报警。

```ts
export const CONTROL_H    = 'h-8';  // 32px 正文控件层：工具条/面板/卡片内一切可点物
export const CHIP_H       = 'h-7';  // 28px 标签层：筛选 chip，比按钮轻一档
export const CONTROL_H_LG = 'h-9';  // 36px 浮层内主动作：对话框底部
```

门禁：白名单式断言，只允许这三档。**新增例外必须在白名单里写明理由**——
否则白名单会退化成「都能过」。

### ② 按钮实现入口唯一

业务组件禁止裸写 `<button>`，一律走 `Button` / `IconButton` / `Chip` / `Segmented`。
ElementPanel 的显隐/锁定按钮曾手写 `<button>`，于是高度、hover 色、圆角、
pressed 态全靠自己抄一遍——抄对了那次，抄漏那次就是「控件漂移」的来源。

例外白名单（结构性卡片按钮，形态由自身语义决定）：
`ThumbCard` / `PalettePanel` / `CuratedSetsPanel`

### ③ 输入框的 Kumo 化

Kumo 输入框是**白底 + 浅描边 + 聚焦内环**，不是「灰底 + 深描边」。
本项目旧写法 `bg-surface-2 + ring-line-input`（为满足 3:1 对比度）导致
输入框成为界面里「挖下去的洞」，比按钮还重。

```ts
// ⭐ 对比度预算花在交互态而非静态态
静态：ring-1 ring-line          // 可分辨边界即可
聚焦：focus:ring-2 focus:ring-brand  // 3:1+ 的可见焦点，满足 WCAG 1.4.11
```

统一走 `primitives.inputClass(extra)`，避免「改了搜索框忘了改数字框」的漂移。

### ④ 与当前画面绑定的操作，紧贴当前画面

分享 / 导出 / 换一版 / 主题切换都在**画布栏**，不在顶栏。

理由：放顶栏会让用户以为分享的是整个应用，实际分享的是当前母题 + 当前配色。
主题同理——它改变的是「这张图看起来多亮」，留在顶栏等于「改完设置再回去看效果」。

### ⑤ 工具条三行结构

```
行① 尺寸 │ 形态参数（滑块 chip）       ← 这张图长什么样
行② 离散选项 │ 视图/产物动作            ← 对这张图做什么
行③ 体积/节点诊断（纯信息，与可点物严格分开）
```

**靠分组而非加大间距区分语义**——间距只是「更空」，分隔线才是「换类别」。
行①②必须相邻：调形状与拿走产物是同一条行为链的两端。

形态参数放在画布正下方而非右栏，因为调线宽/密度是「边看边拧」的行为，
甩到 360px 外让眼睛反复横跳。

### ⑥ 浮层跟随目标而非容器

预览图容器是 `items-center` + 图片 `max-h-full`，图片**常常不铺满**
（比例不同时尤其明显）。主题切换浮层必须用 `useImageBox(imgRef)`
跟踪**图片盒子**，挂容器右上角会飘到图外。与栅格叠加共用同一 hook。

## 三、视觉契约（把审美词量化）

「不优雅」「太单一」「没对比度」这类反馈**肉眼可见、测试全绿**——
椭圆本身完全合法，体积/节点/纯净度全部达标，没有任何断言会失败。
因此必须把模糊审美词**量化成断言**。

### ① 对比度

```ts
// alpha 是把前景往背景上「拉」——线越淡越接近底色，对比度必然下降。
// ⛔ 用 opacity「补偿」对比度是伪命题：
//   实测 graphite 的 line_far 加 opacity:0.62 后，对比度从 2.50:1 **降到 1.98:1**。
//   正确做法是拉宽原色明度（灰阶）。
assert 合成后对比度 ≥ 3:1        // WCAG 1.4.11 非文本对比
assert 不透明度方向性：提高 alpha 只会削弱对比度
```

**下限断言只能说「不够高」，不会说「你用的手段方向反了」**——所以要单独钉一条方向性。

### ② 线宽随分辨率缩放

```ts
unit = clamp(min(W,H) / 1080, 0.5, 4)
strokeWidth = weight * scale * unit
```

取**短边**而非宽边（壁纸从 1170×2532 竖屏到 3440×1440 带鱼屏跨度极大）。
clamp 上限防 7680 超宽屏线细成发丝，下限防缩略图粗成色块。

⚠️ 这是铁律 6「禁止硬编码具体像素」的**盲区**：
铁律管的是「别写 1920」，管不到「`stroke-width` 会不会在 4K 下细到看不见」。

### ③ 形态多样性需用消融实验检测

断言「三层形态不同」在「强制三层同形态」的变异下**照样全绿**——
因为形态只是四个层次维度（疏密/线宽/振幅/形态）之一，几何指纹天然不同。
它测的是「三层不一样」，不是「三层形态不一样」。

✅ 正解：**消融实验** —— 固定其余三维，只留形态在变，此刻几何仍不同才算生效。

### ④ 真实形态的特征量化

以 cloud-bands 为例，「像云」这个审美词被拆成两条可断言的特征：

1. **底缘平直** —— 积云底部被大气压压平，是水平直线段。**贡献约 70% 的像云感**
2. **顶部多个圆弧凸起** —— 大小不等、非对称（对称即暴露程序感）

只断言「函数存在」是没用的（那只是函数名），必须解析真实 SVG 的 `d` 属性。

## 四、视觉设计的硬指标

| 项 | 阈值 | 出处 |
|---|---|---|
| 最弱线束 vs 底色对比度 | ≥ 3:1 | WCAG 1.4.11 |
| 控件高度 | 32/28/36px 三档 | 本项目自定 |
| 正文/按钮字号 | 14px | Kumo `content-text-size` |
| 圆角同心关系 | 外 = 内 + padding | Kumo `concentric-border-radius` |
| hover 颜色过渡 | 0ms | Kumo `hover-color-transitions` |

## 五、颜色与「暗房」原则

界面外壳保持中性、去饱和，把**所有色彩预算留给画布里的壁纸**。
`--vw-brand` 只用于「选中 / 焦点 / 主操作」三类状态，不参与任何装饰性表达——
用户看到的第一个彩色物体应该是壁纸本身。

**纯色元件占比 ≥50%**（母题硬指标）：
- 纯色元件改色 = 整块变色（**换肤**）
- 渐变元件改色 = 只染一端（**染色**）

渐变可做「层」不可做「面」。
